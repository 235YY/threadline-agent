# API 响应与长期缓存核验

## 响应链

- `BRAIN_UPSTREAM_SSE=1` 让 DeepSeek 以流传回模型结果。宿主收齐最终 usage、结束原因和 `[DONE]`，使用原请求账本和 Decision 提交流程。网关的 `stream: true` 仍然是提交后的输出，不能用它衡量上游首段正文。
- 无凭据的公网连通探测成功后，同一模型实例可在 30 秒内复用结果。失败不缓存，实际调用失败会清除缓存。每次仍核验预算、凭据、请求记录和调用准入。
- 前台消息优先于到期反思。记忆反思在 50 个新事件时到期，或在至少 4 个新事件积累 2 小时后到期。较小批次最长等 6 小时。已经到期的空闲反思可合入同一次记忆反思。保留原空闲反思节奏和夜间规则。

## 可选试验开关

- `BRAIN_COMPACT_REFLECTION=1` 开启记忆反思的增量交付。首次或缺少可信边界时走完整输入。之后按固定事件的入账时间去掉上一批的普通对话，保留同毫秒入账和迟到事件。固定材料、当前状态和权限照常交付。显式查阅和跟进仍走原路径。独立的 Auto-Dream 未改变。
- `BRAIN_FAST_CHAT=1` 给启用网关且已连接模型的 Studio 开放 `<模型名>:fast-chat`。主人 Bearer 凭据、`Idempotency-Key` 和 `stream: true` 必填；仅接受调用方提供的普通文本对话，加当前居民静态人设与语言风格。上下文最多 32 条、24 KB，输出上限 1024 tokens，使用 DeepSeek 非思考模式。正文分段转发，常见密钥格式经过脱敏。结果经过原 Journal 结算后才发送结束帧。断流保留未决，客户端用同一键不会重发。
- 快轨不创建 Event、Decision 或记忆，不访问宿主工具，后续聊天历史由调用方携带。需要主脑上下文、语音净化、任务或写入的请求继续选择现有模型名。两个试验开关默认关闭。现有缓存排版仍单独选择，便于拆开量化收益。

## 从调用方测响应

`bench-api-channels.mjs --probe <request.json> --send-one` 直接向 `http://127.0.0.1:<port>/v1/chat/completions` 发一次请求。文件给出 `endpoint`、`scene`、唯一 `idempotencyKey` 和 OpenAI 请求 `body`。凭据从 `THREADLINE_BENCH_GATEWAY_KEY` 读取。测流式时设置 `body.stream=true`，如果还要请求标准 usage，令 `body.stream_options.include_usage=true`。使用隔离居民和独立会话，以免基准对话进入日常记忆。启用联网模型的实例会按正常规则产生费用。

首段只计非空正文，完整回复要求格式正确且流结束。断流、空回复和 HTTP 拒绝会留下结果，探针只提交一次。分组汇总按 API 交付方式区分 JSON 与 SSE，幂等重放不重复计为有效回复。直接 API 延迟与上游模型账本延迟分组。每组全部费用均能从官方记录核对时，可填入每笔的 `officialCostMicros`，随后报告官方每条有效回复成本；否则保留为空。请求账本提供缓存 tokens 和按用量估计的成本。

## 长期缓存对照

DeepSeek 的上下文缓存复用共同前缀，命中由实际返回的 tokens 确认。保留稳定的规则、人设与能力表，将当前时刻、权限、临时检索和当前消息放在后部。对话历史使用同会话的有界窗口。默认排版仍为 `legacy`，试验排版为 `staged-v1`。[DeepSeek 上下文缓存](https://api-docs.deepseek.com/guides/kv_cache/)

```sh
node tools/ops/compare-wire-layout.mjs <journal.json> --json
node tools/ops/bench-api-channels.mjs <journal.json> --json
```

两条汇总命令只读，默认纳入整份账本。API 会话独立分组，真实发包布局以请求账本为准。对照时按来源、模型、推理设置、输出上限和是否启用上游流式分层。在自然使用节奏下采集多个完整日，包含冷启动、夜间间隔、窗滚动和短时连续聊天。用独立会话运行两组，保持同场景、相同设置，避免每条消息来回切换排版。按缓存命中 token 除以全部输入 token 计算加权命中率，同时核对每次有效回复成本、输入长度、首段正文、模型结束、客户端可见回复的 p50/p95，以及通过率和回退次数。客户端可见时间在调用方记录，不能以模型网络耗时替代。没有数据的指标为空。

试验排版也覆盖普通 `reflection`。它在完整的固定包核验后，才将已交付的人设和表达风格前置，并把 `packetId` 移到末尾。当前状态、权限和证据仍逐请求加载。这个变化只提高可复用前缀长度，反思输入减量需要另外核验。普通反思与 Auto-Dream 长期巩固分别统计。

现有 `:work` / `:raw` 仍保持拒绝未支持功能。后续启用前需要让外部工具链保真、预算与请求身份延用现有权威、内部记忆默认保持私有。异步记忆写入需走现有定版引用及事务校验。在此之前，现有空闲巩固继续使用原路径。
