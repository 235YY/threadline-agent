## 这一轮实际交付

- **记忆反思减重**。可选 `BRAIN_COMPACT_REFLECTION=1`。只有上次已提交的记忆反思实际包含入账边界时才建立边界。下次记忆反思按固定事件的入账时间收窄普通对话时间线，保留同毫秒及迟到入账，固定材料原样保留。缺少可靠边界、后续显式 lookup 和主动跟进使用原投影。Auto-Dream 有自己的水位和结算，此次保持原路径。在 36 条合成对话、1 条旧固定材料的离线样例中，完整包从 77,069 字节降到 30,751 字节，约减 60.1%。该数据衡量序列化体积，真实输入 tokens 另测。
- **缓存排版**。试验 `staged-v1` 的稳定配置按人设、风格、当前工具契约顺序排放。当前权限、状态、时间、场景、临时资料继续实时交付。回放旧的格式恢复时按旧排版重建。普通反思也可用上轮实现的固定配置前置。当前没有跨会话全局锁，未来长任务如需固定快照，锁定范围只包含授权一致的静态配置，撤权及时生效。
- **可选 API 真流式快轨**。Studio 的 `BRAIN_FAST_CHAT=1` 开放 `<模型名>:fast-chat`。调用方带主人 Bearer 凭据、独立 `Idempotency-Key` 和 `stream: true`。只传静态居民设定和调用方的文本历史，禁止工具与结构化输出，上游关闭思考、输出最多 1024 tokens。不会写 Event、Decision、笔记或 Process。输出在安全文本边界分段，保留常见密钥脱敏并排除 `reasoning_content`。复用同一居民 Journal 和预算准入，完整 usage 和正常结束后才发末帧。断流保留 UNKNOWN，重复键与重启都不会自动补发请求。
- **保留完整心智入口**。普通 API 继续事务采用后再交付。语音、任务、记忆写入和需要历史的请求继续走原协议。`:work` 与 `:raw` 仍按现有网关能力拒绝。快轨没有自动分流或隐式降级，调用者显式选择。

## 接下来如何比较

- 从调用方用 `tools/ops/bench-api-channels.mjs` 直接打 `/v1/chat/completions`。用多个完整自然日对照，单独比较普通心智入口的 `legacy` 与 `staged-v1`、全量反思与增量反思、快轨与完整聊天。控制模型、场景、推理设置以及上下文上限。快轨的取舍需要另测答案质量和连续性，不能只比首段。
- 记录首段正文和完整回复的 p50/p95、通过率、回退、加权命中率和每条有效回复费用。区分供应商用量估算和官方扣费。无官方逐笔记录或隔离对照时，真实单回复成本保持未知。费用比较计入所有相关尝试，包括格式恢复和后续查阅。
