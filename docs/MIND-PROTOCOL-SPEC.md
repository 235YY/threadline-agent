# Threadline 心智 API 运行契约（v2.7）

Studio 本地网关提供 OpenAI Chat Completions 的文本子集。心智状态和事实仍由当前居民的 ContinuitySession、SQLite 和 RequestJournal 管理。API 格式与居民认知模式是独立的两项契约。

## 可以使用

- 网关监听 `127.0.0.1`，对话、状态、场景和局末接口需要主人的本地网关凭证。感官推送和读取使用独立的居民限定凭证。
- `GET /v1/models` 仅列出当前实际可用的模型名、`:chat`、`:voice`、`:call` 和 `:game`。`GET /v1/protocols` 同时提供场景设计草案与网关实际能力。
- `POST /v1/chat/completions` 接收用户和助手的文本消息，将最后一条用户消息送入居民的认知事务。历史由居民自己按场景读取。用 `X-Threadline-Scene` 指定会话；缺省使用合法的 `user` 字段或 `default`。不同场景的近轮对话、事件来源和世界快照各自寻址。主人仍可访问居民为主人共享的记忆。
- `stream: true` 在决定提交后以 SSE 回放同一段正文。只有 RequestJournal 可提供完整用量时才返回用量；支持 `stream_options: {include_usage:true}`。语音预设可净化文本并返回展示用 `threadline.actions`，这些提示无需执行权限，因为它们不派发电脑或游戏动作。
- 可选 `Idempotency-Key` 将同场景并发的相同请求合并，键冲突返回 409。入站事件用固定身份保存，重启后可恢复该事件已提交的回复和用量，或返回状态不可用。跨重启只保证固定文本来源不重复触发认知，响应格式、完成对象 ID 和临时前缀缓存可能重新生成。
- `POST /v1/world/state` 维护有界、会过期的 RAM 最新快照，支持标量字段和 numeric deadband。`GET /v1/world/state?sceneId=…` 读取当前场景快照。此通道目前不向真实模型投影。
- `POST /v1/sessions/end` 根据该场景已有、确实处理过的事件提取最多两条候选，来源使用仓内固定版本。它不接收调用方传入的证据，不自动写记忆。重复请求只重新读取历史并返回候选。
- 连续三次模型链路故障进入短暂冷却，返回 503 与 `Retry-After`。已有的预算、串行和未知结果保护仍由运行时负责。网关外部事件不会直接执行宿主工具。

## 十四条款的落实范围

| 条款 | v2.7 状态 |
| --- | --- |
| 1. 受众隐私 | 支持主人场景。朋友和公开调用在认知前拒绝，待全部材料路径完成隐私裁决。 |
| 2. 世界状态 | 有界覆盖快照已接外部 API。认知投影待验证。 |
| 3. 上下文分流 | 文本进入心智链路。工作、透明、机器辅助请求明确拒绝，不污染居民记忆。 |
| 4. 说话节律和断连 | 可识别断连。认知开始后仍按事务收尾。语音实际播放确认与半句入账未接。 |
| 5. 输出模态 | 普通文本、语音净化与动作提示可用。结构化输出和外部工具协议待接。 |
| 6. 情绪耦合 | 使用居民配置。场景级阻尼保留为设计。 |
| 7. 记忆写入 | 噪音阻挡与局末带来源候选可用。场景级写入路由未接。 |
| 8. 副作用 | 网关当前不派发工具。熔断已在进入认知前生效。 |
| 9. 跨场景注意力 | 使用原有全局串行。优先级抢占未接。 |
| 10. 成本和延迟 | 仍由现有预算与请求账本计费。场景元数据不能提高预算，无首字承诺。 |
| 11. 幂等 | 同会话并发合并与固定入站事件防重。 |
| 12–14. 离线间隔、感官热插拔、硬件急停 | 后续设计。 |

`:raw`、`:work`、`tools`、严格 `response_format`、原始系统消息及每请求推理参数当前无法原样执行。请求会收到 4xx/501，而不是成功返回被降级的结果。外部应用是否能直接接入取决于实际发送字段。IDE 和标准工具调用链尚未通过协议验收。

## 下一阶段，待批准的实施顺序

1. **先接收真实上游 SSE，仍按原事务提交。** 在现有 model-client 解析数据帧，区分提供方首个内容片段、完整正文、终止理由与最后用量。先只统计到达时间及缓存命中，现有 Proposal 仍完整验证、提交后才对外发布。断流无结算时保留 UNKNOWN。参考 [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。
2. **给工作流开保真通道。** 让外部应用拥有其工具调用与工具返回的原始序列，逐项保留 ID、索引、参数片段、结果和 finish_reason。只加明确授权的心智材料，保留消息和工具的稳定前缀。外部工具不自动映射为宿主授权。为提供方差异做协议测试，禁止将内部思维链转发客户端或写成主体记忆。参考 [DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。
3. **把慢记忆移出回复关键路径。** 快路径只提交已有事实、决策、响应和必要状态。复用现有维护入口，用已提交的事件固定版本处理选出的候选。处理结果待下一轮合规检索，重启时复用原请求与事实。
4. **先测成本与能力再调大窗口。** 比较同一模型、任务和参数下的协议正确率、上下文续接率、真实用量、加权缓存命中率、首个上游内容和最终可交付回复的 p50/p95。优先确保工具反馈及近期对话完整，再给相关记忆独立限额。游戏和语音用短输入与快推理配置，工作保留长历史及按任务授权。不同指标单独报告。

提交前播放的真流式语音和公开受众的材料隔离都涉及新协议边界，需要先确认。声音设备的播放回执与网络写出成功是两种不同事实。
